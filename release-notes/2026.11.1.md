ThinkWatch Lite now bundles Core 0.89.0, which automatically adjusts CPU execution and buffering to traffic and available machine or container resources. No configuration changes are required.

- Core keeps a small permanent I/O scheduler and grows CPU execution threads on demand. A sufficiently provisioned 80-core server can run 80 CPU jobs concurrently; extra execution threads retire after ten idle seconds. Parsing, privacy filtering, rewriting, decompression and plugins share CPU admission.
- Release Core binaries use mimalloc to reduce allocation fragmentation and retained free pages. Linux also disables transparent huge pages for the Core process where permitted and respects cgroup memory limits.
- Concurrent request buffers share a memory budget. When occupied, new requests receive a retryable 429 with `Retry-After`; reservations follow buffered data through its final reference. This budget is not a hard limit on total process RSS.
- The desktop shell keeps one or two I/O workers for control traffic, with extra blocking threads retiring after ten idle seconds. Gateway execution remains in Core and can use the available CPUs under load.
- Archive and updater dependencies include security fixes. Windows portable-package handling rejects malformed archive filenames, and development dependencies have also been updated.

The control-plane protocol remains 58 and the request-store schema remains 28. Existing settings, upstreams, request history and usage history are kept. Remote connections continue to work with protocol-58 servers; upgrade a remote Core to 0.89.0 to enable automatic resource management there.
