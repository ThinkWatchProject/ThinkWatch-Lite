Aliases now offer an opt-in “Show only the alias in client model lists” setting. Enable it to hide the mapped upstream IDs from OpenAI, Anthropic, Gemini and native Codex model discovery while keeping the alias visible. Existing aliases keep their current behavior until the setting is enabled.

The editor previews the original names that will be hidden. Routing suggestions omit those originals by default but still find them when searched or when editing an existing value. Permission editors keep all model IDs and indicate hidden originals; upstream targets and request history stay complete. Hiding a name does not revoke access to it: existing model permissions and routing still govern direct requests.

The setting reloads live, is preserved in configuration packs and remains intact when an older client edits the alias. A client may need to refresh its own model picker. Connecting to an older Core disables the new control and explains that an upgrade is needed.

This release bundles Core 0.92.0. The control-plane protocol remains 58 and the request-store schema remains 28. No database migration is required.

The past-year usage heatmap no longer outlines every day in the selected overview range. Cells retain their usage colors, with a subtle hover highlight and a clear keyboard focus indicator. Day details and keyboard navigation continue to work.

Multi-turn reasoning history now follows the actual upstream's capabilities. The gateway automatically learns from precise request-validation errors, retries one adjustment and remembers accepted omissions in a scoped 24-hour runtime cache. No additional setup is required. Signed history and explicit settings are preserved.
