**Upgrade notes:**
- The bundled core is now 0.74.0. The control-plane protocol stays at 48, so remote servers on core 0.73.0 keep working.
- Nothing is cleared; the request history, stored payloads and settings carry over.

**Secrets & privacy:**
- Only the text written in a request is searched: system prompts, the messages of every role, reasoning, tool-call arguments, tool results and tool descriptions. Ids, model names, signatures and other values the protocol needs are sent as they are. With the mobile-number rule on, a run of digits inside a Codex reasoning item id used to be replaced, and Codex then failed on every later turn of that conversation with `invalid 'input[n].id'`.
- Requests to paths the app does not recognize, and request fields outside the written text such as `metadata`, are no longer searched.

**Notifications:**
- A rule that matches again within 5 minutes of its notification no longer brings a second notification when those 5 minutes end; its count in the notification list goes up instead. The next match after the 5 minutes notifies right away.

**Security page:**
- Rule groups no longer have a checkbox that switches all of their rules at once.
- The action menus in the rule list no longer cut off the bottom of their text.

**Upstreams:**
- In the connection step of the upstream dialog, the locked auth-header row names the header (for example `Authorization: Bearer` or `x-api-key`) as soon as a protocol is chosen, before the address is filled in.
