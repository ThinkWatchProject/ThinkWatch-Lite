This release bundles Core 0.96.0 and adds automatic adaptation between upstream streaming and non-streaming responses. Requests follow the client's mode first. After an eligible upstream API rejection, the gateway can try the opposite mode once and convert a successful answer back to the client's requested protocol and framing, preserving tool calls and usage. A complete successful trial teaches a working preference for 30 minutes; configuration reloads clear it. No additional configuration is required.

Failed trials preserve the original error, and partially delivered answers are never replayed. Authentication, quota, rate-limit, overload and timeout errors do not trigger mode trials. In particular, `Rate limit exceeded` alone is not evidence that non-streaming requests are unsupported. Converting a whole answer into a stream still waits for the upstream to finish. WebSocket requests and native output contracts that cannot be preserved by conversion are excluded.
