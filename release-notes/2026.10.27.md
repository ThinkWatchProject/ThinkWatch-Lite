**Upgrade notes:**
- The bundled core is now 0.80.0. The control-plane protocol stays at 51, so a remote server running core 0.79.0 still connects; the refused requests described below appear only with 0.80.0.
- Nothing is cleared; the request history, stored payloads and settings carry over.

**Refused requests show up in Traffic:**
- A request whose model name does not exist, is not allowed for its key, or whose alias or specified model does not resolve now appears in Traffic as "Model unavailable". The request details give the model name and the reason.
- A request that no rule decided on, or one made before any upstream is added, appears as "Not routed".
- Requests without a valid gateway key are still not recorded.

**Interface size:**
- Settings > General has Interface size: 90%, 100%, 110%, 125% or 150%. The whole interface scales, including the update and connection windows.
- Cmd (Ctrl on Windows and Linux) with = enlarges, with - reduces, and with 0 resets to 100%.
- The size is kept on each computer and is not synced.

**Clients:**
- Clients can be reordered by dragging the handle at the start of a row, or with Move up and Move down in the row menu. Alt+Up and Alt+Down move the focused row. The order is kept on this computer, and clients in WSL follow the same order.
- On Windows, the WSL notes now say that mirrored networking is a WSL setting. On Windows 10 and Windows 11 21H2 they explain that WSL uses NAT, so the gateway on Windows cannot be reached from inside WSL, and that WSL's mirrored networking mode needs Windows 11 22H2 or later.

**Menu bar (macOS):**
- The numbers next to the menu bar icon use 9 pt regular type, matching other menu bar readouts.

**Gateway keys:**
- The usage limits hint in the key dialog says that a full minute or hour limit makes requests wait, and only a used-up day, week or month limit rejects them until it resets.

**Security:**
- The app and the core use `rustls-webpki` 0.103.16 (RUSTSEC-2026-0382) and `webpki-root-certs` 1.0.10 (RUSTSEC-2026-0383).
