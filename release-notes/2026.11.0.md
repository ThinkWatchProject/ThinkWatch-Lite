This release bundles ThinkWatch Core 0.88.0, expands privacy filtering to UUIDs and blockchain credentials, and adds a minimum generation speed for upstreams.

**Upgrade notes**

- The control-plane protocol moves from 57 to 58. Remote servers must use protocol 58 (Core 0.87.x or 0.88.x); upgrade a remote server to Core 0.88.0 to get the new filtering rules there. Local connections use the bundled Core 0.88.0.
- The request-store schema remains 28. Request history, usage history, settings and upstreams are kept.
- The 11 new rules are enabled by default with replacement as their rule action. The default Monitor mode records findings; turning protection On replaces matching text before it reaches an upstream. Existing installations with protection On will hide more identifiers after upgrading.

**Secrets and privacy**

- The built-in catalog grows from 120 to 131 rules, with 102 enabled by default. New rules cover UUIDs, raw wallet key shapes, verified Solana keypairs, Sui private keys, Stellar secret seeds, XRP seeds, blockchain accounts, wallet secret fields, trading credentials, keystores and RPC URL credentials.
- UUID coverage includes ordinary order and trace IDs, plus compact 32-character hexadecimal identifiers. The raw 64-character hex rule also covers indistinguishable transaction hashes.
- Named fields and authentication headers protect opaque keys, secrets, passphrases and signatures used by exchanges, Polymarket CLOB/Builder/Relayer and predict.fun. Short, symbol-first and numeric credentials, escaped JSON fields and pasted recovery material are covered.
- Rule names and coverage descriptions come from Core in Chinese and English. UUIDs, hashes and public accounts do not independently trigger credential-exfiltration blocking. Wallet secrets and the new credential-field findings are fully masked.
- Existing JSON and protocol boundaries remain in place. Keypair byte arrays are protected when pasted as message text. Coverage and limits are documented in the [Core reference](https://github.com/ThinkWatchProject/ThinkWatch-Core/blob/v0.88.0/docs/security/blockchain-redaction.zh-CN.md).

**Upstream generation speed**

- An upstream can be stopped when generation stays below a configured tokens-per-second threshold for a measuring window. The upstream dialog exposes the threshold and window, validates both, and keeps the setting when sharing or importing an upstream.
- Too-slow failures show the measured generation speed in traffic details. Leaving the threshold empty turns the limit off.

**Credit and streamed-error handling**

- Escaped insufficient-credit errors now pause the affected upstream and trigger failover.
- Errors returned inside an HTTP 200 event stream are classified before a completed stream is recorded as successful. Balance and quota failures pause the upstream, and an answer that has already delivered content is never replayed.
