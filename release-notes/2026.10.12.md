**Upgrade notes:**
- The bundled core is now 0.68.0, with control-plane protocol 44. A remote server must be upgraded to core 0.68.0 together with the app: this version does not connect to a server on 0.67.1, and 2026.10.11 and earlier do not connect to 0.68.0.
- **The request history, stored payloads and the security log are cleared on the first start.**

**Overview:**
- The Overview is one screen of six cards — Tokens, Cost, Cache hits, Requests, First token and Traffic — each with its number, the change against the previous period and a small chart. Hovering any chart shows the same hour on every chart; the value appears on the card under the pointer.
- **Needs attention** at the top lists what needs action — failed requests, tool calls that were cut, upstream problems, unpriced requests — and is hidden when there is nothing.
- Cache hits shows how input was split between cache reads, new input and cache writes. First token shows the median and 95th percentile over time; hours without requests are bridged with a faint dashed line.
- The table below lists requests, tokens, cost, cache hits, first token and generation speed by model, upstream or key.

**Traffic:**
- How much each request sent to its upstreams and received from them is recorded, as it crossed the network, together with the proxy it went out through. A request's **Timeline** shows **Egress**, **Upload** and **Download**, and hovering the token count in the Traffic table shows the upload and download.
- **Upstreams › Proxies** has a **Traffic · 24 h** column, with 7 and 30 days on hover.

**Content:**
- A request's **Content** tab has two views, **Parsed** and **Raw**, both live while the request runs. **Parsed** shows the conversation, with the answer appearing as it streams, thinking and tool-call arguments included. **Raw** shows the request and response lines, headers and bodies, with each streamed event appended; **Follow latest** keeps the newest in view. **Client side** and **Upstream side** show what the client and the upstream each exchanged with the gateway, which differ when the format is converted or a plugin rewrites the request. Secrets are replaced as in what is stored.
- Places a security rule matched are marked in both views, in the colours of the security log; a folded part that holds one carries a dot.

**Security log:**
- Each entry opens in place to show every place the rule matched, with the text around it; the rule as it was when it matched; and exactly what was done — the placeholder a secret was replaced with, the tool call that was cut and the notice the client received, or the refusal the client received. The entries of a request's **Timeline** open the same way.
- **Export** saves the selected period as JSON or CSV.

**Codex on a ChatGPT account:**
- Finished turns are recorded as finished, with their tokens and cost. Codex closes the connection as soon as it has read the end of the answer, and these turns were recorded as cancelled; longer sessions also recorded no tokens.

**Routing:**
- On the routing map, requests in flight move along their path from the key to the upstream.

**Menu bar:**
- The cost is written like the token count, with its unit after it (`41.20$`). The opened menu still marks an estimated cost or one that is only a lower bound.

**Fixed:**
- Pressing Space on the Overview no longer scrolls the window into blank space.
