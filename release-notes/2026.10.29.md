**Upgrade notes:**
- The bundled core is now 0.83.1 and the control-plane protocol is 54. A remote server running an older core must be upgraded to 0.83.0 or later to stay connected.
- Nothing is cleared; the request history, stored payloads and settings carry over.
- A routing rule that turned extended thinking on or off (`thinking:` under the rule's `set`) no longer loads, and the app opens in safe mode. Repair removes the field; set the rule's Reasoning again afterwards (Off corresponds to the old "off").
- Updating to this version still restarts the gateway the previous way. Seamless upgrades apply from the next update on.

**Temporary upstream failures are retried:**
- When an upstream fails before the answer starts, because it is overloaded, returns a server error, cannot be reached or drops the connection, the gateway waits 2, 4, 8, then 16 seconds and sends the request again, also when that upstream is the only one. Other upstreams are tried first, and a longer wait asked for by the upstream is respected.
- Retrying stops at Settings > Failover > Wait at most (120 seconds by default), which now covers queueing and retrying together. Setting it to 0 turns both off.
- An answer that has already started is never sent again. Errors caused by the request itself, an exhausted quota, rejected credentials or a rate limit are not retried.
- Traffic shows a request as Retrying while it waits, and the request details mark each retry and how long it waited.

**Reasoning effort in routing rules:**
- A rule can set Reasoning to Off or to a level from low to max, for example to keep requests that Claude Code sends to a GLM upstream at max. A level only changes requests that already have reasoning on.
- When an upstream rejects a reasoning level, the request is sent again once with a level the upstream accepts, and the choice is remembered for that upstream and model. The request details say when and why the level was changed.

**Seamless upgrades:**
- Updates no longer stop the gateway port or cut requests in flight. The running core hands its sockets to the new core and finishes its requests before it exits. Restart Gateway works the same way.
- Homebrew upgrades are recognised and handled like an in-app update. After an update the window comes back as it was.
- The overview and the menu bar count the requests the previous core is still finishing.

**Traffic:**
- Answers, thinking and system prompts in the request details and in conversations render their Markdown: headings, bold, lists, tables and code blocks. HTML in an answer is shown as text, links are not clickable and images are not loaded.
