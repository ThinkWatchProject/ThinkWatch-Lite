Web search and page reading can now run in Core. Configure the execution mode under **Routing → Auxiliary**, choose automatic search engines or set your own preferences, and test search, page reads, and find-in-page directly from the app. Language and country/region follow the connected Core host by default, with searchable choices by name instead of code inputs.

On macOS, the menu-bar menu now runs in a dedicated accessory process, allowing it to open over other applications’ full-screen spaces while the main app keeps its normal Dock behavior. The same implementation is used on all supported macOS versions. Menu updates, actions, language, and theme stay synchronized, and the helper exits with the main app or restarts after an unexpected exit.

This release includes ThinkWatch Core 0.97.0. Recognized Claude Code standalone WebSearch requests can avoid an auxiliary model call; web tools in ordinary conversations still return results to the main model, whose normal usage remains billed. Core execution is opt-in and does not require MCP or a search API key.
